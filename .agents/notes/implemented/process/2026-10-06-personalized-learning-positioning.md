# Agent Note: Product positioning follows the personal learning loop

Status: implemented

## Problem

A collaboration-first introduction obscures why users would choose Choruz over their existing agent workspace. A broad self-improvement claim can also imply unimplemented harness support, model-weight training or guaranteed savings.

## Decision

The README leads with user interaction traces, asynchronous analysis, personalized benchmarks, measured harness adaptation and selective smaller-model execution. Collaboration remains an enabling capability rather than the primary promise. The introduction distinguishes fixed analysis/evaluation standards from changing worker instructions and orchestration.

Capability boundaries remain visible in the lead: native trace learning supports Claude Code and Codex; Muse CLI workspace support does not imply a Muse learning adapter. Smaller-model use refers to a provider model the user configures, not automatic certification of its size or cost. Completion requires a validated applicable program, provider configuration and explicit consent. The narrative makes no general error-rate, speed or billing guarantee.

Promotional media follows [the existing evidence-chain policy](2026-09-06-demo-recording-evidence-chain.md). Illustrated overviews are labelled as illustrations, not live benchmark results. Published media stays in repository attachments or a separate media branch, with a README entry and artifact provenance.

## Alternatives considered

**Lead with a Slack-like multi-agent interface.** This describes the collaboration mechanism instead of the personal learning outcome that motivates the product.

**Advertise improvement across every supported CLI.** A CLI execution adapter is not evidence of native trace ingestion or harness evolution support.

**Present animated diagrams as measured product runs.** This obscures evidence and can invent successful outcomes or cost savings.

## Consequences

Marketing and capability boundaries share the same introduction. [Task-first workbench](../feature/2026-09-29-task-first-workbench.md) remains active because it owns navigation and task execution, not positioning; the recording note remains active because it owns capture and publication truthfulness. Neither decision is superseded.
