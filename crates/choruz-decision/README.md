# Choruz decision

Typed Choice, Score and Noul inference with a caller-supplied `Provider` or Choruz's client for the official TypeSafe HTTP API. This is not an official TypeSafe Rust SDK. The library validates question sets, answer distributions and selected options before returning decisions. It owns no credentials store, database, scheduler or tool permissions.

Questions preserve string, object and array instructions and rubrics without stringifying structured content. Choice options may have null descriptions; Noul accepts optional `true`/`false` criteria. Choruz requires meaningful instructions, two or more Choice/Score alternatives, and bounded content even where an upstream SDK accepts broader inputs. Each request batches independent questions: a head cannot read another head's answer. Dependent browser steps obtain new observations and issue separate requests.

The implementation follows the [official question types](https://github.com/typesafe-ai/typesafe-sdk-python/blob/0ffd094c72ed9445223060b24ffd7a56aa781fb4/src/typesafe_sdk/_core/question_types.py) and [HTTP contract](https://docs.typesafe.ai/api). The background builder's [instructions](../choruz-learning/assets/decision-program.md) adapt the [official design skill](https://github.com/typesafe-ai/skills/blob/65a39f393687675ce170e6094757de20370365b9/skills/typesafe-ai/SKILL.md) to Choruz's declarative formats. No upstream Python runtime, arbitrary generated code, or dynamic skill download runs in the worker. Upstream attribution is in the repository NOTICE.

`Client::new` accepts a device-local API key. Requests use the fixed HTTPS endpoint with no redirects or automatic retries. Transport errors omit provider bodies and credentials. Requests and responses have bounded sizes and timeouts; cancellation drops the in-flight request.

`programs::Program` describes a finite-output task with an applicability question and explicit abstention. `task::DecisionTask` applies the stricter of the program's confidence threshold and the caller's threshold. Confidence is a routing signal, not a correctness score. Classification and progress advice do not modify the independent evaluator or execute suggested actions.

`programs::SelectedProgram` pins execution to the model identity used for evaluation. With `assist_turns`, the selected program supplies advice before native execution. Separately enabling `complete_turns` permits an applicable, sufficiently confident finite answer to finish the turn without native inference. The answer must be one of the evaluated program's output choices; it cannot authorize tools or claim filesystem changes. An abstention, rejected result or unavailable provider falls back to the native Agent. Both modes require learning and a selected validated program, and authorize sending task inputs to TypeSafe on the execution device. The controller checks consent at dispatch and selection again before accepting the result. Foreground inference has a five-second budget. Structured sessions reserve the turn before inference to reject duplicates and honor cancellation.

Completed finite answers retain model identity, provider usage and a native-call-avoided count in the existing session journal or reply event. Subsequent native execution receives pending finite-answer context. Structured completions also create a deduplicated `runtime.decision` event for learning without a second chat bubble. Neither token counts nor avoided calls are a dollar-savings estimate.

`programs::browser_action` chooses an operation and target from a supplied observation. It does not open a browser, generate text, execute actions or verify completion. An executor must establish current observation identity, authorization and outcome checks independently.

`workflow::Workflow` composes at most sixteen semantic clicks, text entries and fixed-value native dropdown selections. Each step resolves fresh targets on an explicitly listed page and returns control on ambiguity, low confidence or an uncertain mutation. Dropdown values are option values, not display labels. Independent visible-text checks must be absent before execution and present afterward; these checks are not proof of business correctness. The caller owns authorization, deadlines and browser-session cleanup.

`workflow::run_with_assistant` can resolve up to two abstentions through an injected reasoning Agent. The assistant sees only the current approved targets, URL and step goal; it cannot alter the manifest, input values or outcome checks. A changed provider model, ambiguous target set or uncertain browser mutation still stops execution. Receipts separate decision proposals from attempted browser actions and their acknowledgements. An acknowledgement does not replace the final independent check.

In Choruz, enable browser automation in the Agent's Experience settings after enabling learning and selecting a program-building Agent and decision model. Permission selects the device's BrowserSkill identity, exact page URLs and permitted task scope once. The selected device needs enabled BrowserSkill and its own TYPESAFE_API_KEY. Drafts remain visible in history without execution forms.

The bound Agent discovers learned workflows and supplies current inputs, text-writing instructions and independent expected text. The first current requested task validates a draft; historical tasks are never replayed for validation. Task matching cannot expand the configured pages or device/account fingerprint. The backend serializes admission, rechecks permission after matching and refuses failed or uncertain revisions. Successful page checks permit later reuse, not a claim of general business correctness.

Native Codex or Claude assistance uses the binding's account in a fresh, tool-disabled conversation on the same device. It may resolve bounded target abstentions or generate named text fields, not add actions, change option values or supply success checks. The run deadline and cancellation cover the browser and assistant. Receipts retain field names, elapsed time and provider-reported tokens, not input/generated text; those tokens exclude native Harness usage.

The [bound helper](../choruz-host-runtime/assets/agent-templates/extensions/browser-workflows.md) returns durable non-chat receipts. Discovery and execution completion schedule a continuation in the originating conversation. Stable request and continuation identities prevent duplicate actions and duplicate wakeups after restart. Stop disables new admissions and requests cancellation; already-dispatched effects cannot be recalled. Failed or uncertain effects require inspection before repair through the existing asynchronous learning process.
